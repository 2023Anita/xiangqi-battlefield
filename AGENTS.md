# AGENTS.md — structure & conventions for xiangqi-battlefield

Single-page 3D xiangqi game. **The shipped artifact is `index.html`, generated by `node build.js`. Never hand-edit `index.html`; edit `src/` and rebuild.**

## Layout

```
index.html               GENERATED single-file build (works on file:// and GitHub Pages)
build.js                 inlines vendor + src into index.html
src/
  index.template.html    HUD markup + CSS (classical Chinese style); <!--SCRIPTS--> placeholder
  engine.js              rules engine (classic script, UMD: window.XQ / module.exports). No DOM.
  ai.js                  search (window.XQAI / module.exports); also self-registers as Worker onmessage
  main.js                ES module: renderer, camera, tweens, FX, piece animation, game controller, HUD, online protocol
  board2d.js             ES module: 2D Canvas board (fallback renderer when WebGL is unavailable or ?renderer=2d)
  models.js              ES module: toon/outline/sketch materials, Kit (primitive baking), unit builders, battlefield
  audio.js               ES module: procedural WebAudio Sfx
  net.js                 ES module: GameTransport interface; PeerTransport (PeerJS/WebRTC), RelayTransport (MQTT over WebSocket), HybridTransport (direct→relay fallback, used by main.js)
vendor/                  three.module.min.js r170, addons (OrbitControls, EffectComposer, UnrealBloomPass, OutputPass, BufferGeometryUtils + deps), peerjs.min.js 1.5.4, mqtt.min.js 5.16.1 (MQTT.js browser build, global `mqtt`)
test/
  engine.test.js         node: perft + rule cases + notation + save/load + AI sanity
  browser.test.js        playwright: AI worker; two-page online play (use --local-broker in sandboxes without internet WebSocket)
  fallback2d.test.js     playwright with WebGL disabled: 2D fallback, real clicks, undo/hint/save-load, AI, online (--local-broker), screenshots fallback-2d*.png
  relay.test.js          playwright 2D pages over a LOCAL MQTT broker: relay=only full flow, PeerJS unreachable → relay, WebRTC blocked → relay after 6 s, screenshot relay-mobile.png
  mqtt-broker.js         aedes + ws MQTT-over-WebSocket broker for tests (needs aedes@0.51, ws in ../.pw/node_modules)
  screenshots.js         playwright + SwiftShader screenshots into screenshots/
  run-screens.sh         sandbox helper (expects ../.pw/node_modules and ../.pw/browsers)
screenshots/             reference renders
```

## How the build works

ES modules are embedded as `<script type="text/plain" data-mod="three" | "three/addons/…" | "app/main.js">`. A tiny bootstrap converts each into a `blob:` URL, installs an import map, then imports `app/main.js`. Relative imports inside addons are rewritten to bare `three/addons/...` keys; `./x.js` in `src/` becomes `app/x.js`. `engine.js` and `ai.js` are normal classic scripts (ids `xq-engine-src`, `xq-ai-src`); the AI Web Worker is created from their concatenated `textContent` via a Blob, with a main-thread fallback.

## Engine conventions

- Board `Int8Array(90)`, `sq = r*9 + c`; `r=0` Black back rank (top), `r=9` Red back rank. World: `x = c-4`, `z = r-4.5` (Red near the default camera, +Z).
- Pieces `K1 A2 B3 N4 R5 C6 P7`, Red positive / Black negative. Move int `from*90 + to`.
- `Position.serialize()` = `<startFEN> moves <iccs…>`; `Position.load()` accepts plain FEN too. ICCS: file `a–i` = c, rank digit `9-r`.
- `status()` treats stalemate (困毙) as a loss for the side to move; 120 plies without capture (`nocapture`) / no attackers = draw.
- Repetition (3rd occurrence of position+side) is adjudicated by `cycleVerdict(start)` over the moves since the previous-but-one occurrence (simplified Asian rules): a side that checked on every move while the other did not → `perpetual_check` (loses); else a side whose every move was a chase or check (一将一捉 counts) while the other's was not → `perpetual_chase` (loses); otherwise `repetition` draw. Result objects carry `winner` and `loser`; `XQ.resultText(st)` gives the Chinese reason (红方长将，判负 / 黑方长捉，判负 / 循环局面，和棋 / 六十回合无吃子，和棋).
- Chase (`moveInfo(m).chase`): after the move, any piece of the mover (moved or discovered) newly has a legal capture of an enemy piece that is not the general, not an uncrossed pawn, not attacked by a king, not the same type as the attacker (兑子), and is either unprotected or a 车 attacked by 马/炮/兵. Computed lazily (no per-ply bookkeeping in `makeMove`, so perft speed is unchanged); `cycleVerdict` unmakes/remakes the cycle in place and restores the position exactly. Undo = `unmakeMove`, nothing else to restore.
- AI: a repetition inside the search (2-fold within 30 plies) is scored with `cycleVerdict`: ±`PERP` (6000, below mate scores) when one side would be the perpetual checker/chaser, else 0.
- Perft must stay 44 / 1920 / 79666 / 3290240.

## Rendering conventions

- Renderer choice happens at the top of `main.js`: `?renderer=2d`, no WebGL2 context, or a throwing `WebGLRenderer` → `MODE2D`. In 2D mode the original canvas is replaced by a fresh one, `board2d` draws everything from `game` state each frame, `setupPieces/syncPieces/animateMove/onResize/simStep/frame` delegate to it, 3D-only buttons (`.only3d`: 2D 俯视, 光照, 草图模式, 字牌) are hidden, and a toast says 当前设备不支持 3D，已切换到 2D 棋盘. The THREE scene objects (markers, FX) are still constructed but never rendered; the battlefield is skipped. Keep new 3D-only code behind `MODE2D` checks and new game-state features renderer-agnostic (read `game.*`, not meshes).

- All unit geometry comes from primitives via `Kit` (vertex colours + per-primitive inverted-hull outline). Each piece has an articulated rig (`unit`, shown only while animating) and a merged static copy (`stat`, 2 draw calls) — call `piece.articulate(true/false)`.
- Forward for unrotated units is −Z; Black units are rotated π in `holder`. The base disc/medallion lives in `disc` and is rotated to face the viewer side.
- Sketch mode = `SK.uSketch` uniform (shared by every patched material): white albedo + screen-space hatching in dark tones; `noHatch` materials go greyscale instead.
- Animations use `tween()` on a sim clock (`simTime`, `timeScale`); tests can freeze on `emitEvent` names (`projectile-mid`, `impact`) via `__xq.events.pauseOn` and step with `__xq.advance(sec)`.

## Online protocol (host authoritative)

Messages over `GameTransport.send`: `move{m,ply}`, `sync{pos,hostSide,result}`, `hello`, `needSync`, `undoReq/undoAns{ok}`, `drawOffer/drawAns{ok}`, `resign`, `rematchReq/rematchAns{ok}` (rematch swaps colours). The host validates every incoming move (`ply` must match, side must be the guest's, move must be legal) and replies with a full `sync` on mismatch and on every (re)connection. Peer id = `xqbf-<code lowercase>`. Optional broker override `?peerserver=host:port/path`. After applying a guest move the host immediately sends a full `sync` (heals a resync that crossed the move in flight).

### Transports (src/net.js)
- `HybridTransport` is what `main.js` creates. Host: starts PeerTransport AND RelayTransport; whichever sub-transport a guest session opens on (`_open`) becomes `active` (a later session on the other one takes over). PeerJS errors never fail the host while the relay is up; `unavailable-id` on a fresh room → error (main picks a new code); on a resumed room → retry PeerJS later. Guest: PeerTransport first; not `connected` within 6 s or any PeerJS error → drop it and use the relay for the rest of the session (one exception: relay brokers unreachable after a *timeout* fallback → one unhurried WebRTC retry). Status info carries `mode: 'direct'|'relay'` → pill 已连接（直连）/已连接（中继）.
- `RelayTransport`: topics `xqbf/v1/<CODE>/host|guest` (each role publishes on its own, subscribes to the other) + retained `…/presence` `{h: hostInstanceId}` (host only; cleared on close and by last-will). Connects to ALL brokers in the list (public brokers are not bridged) and listens on all; sends on the broker it last heard the peer on. Envelope `{k: hello|ack|nack|ping|msg|bye, f: senderId, to, q: seq, d}`, QoS 1, dedupe by per-sender seq; game messages sent while offline are queued and flushed before the re-hello. Heartbeat 5 s, peer lost after 20 s; guest re-hellos on broker reconnect / host presence change; host re-links any guest that talks to it while unlinked. No presence and no ack 7 s after the first broker connect → `peer-unavailable` (房间不存在或房主已离开).
- URL params: `?relay=only|off`, `?mqtt=ws://host:port/mqtt[,…]` (overrides the public broker list; carried in invite links like `peerserver`). `relay`/`renderer` are kept in the player's own URL (reload) but not in invites.

## Testing checklist before shipping

1. `node build.js && node test/engine.test.js` (all PASS)
2. `node test/browser.test.js ai`, `node test/browser.test.js online --local-broker` (forces `relay=off`; on slow software-GL sandboxes add `XQ_Q='&renderer=2d'`, two 3D pages take >100 s to load), `node test/fallback2d.test.js --local-broker` (WebGL disabled) and `node test/relay.test.js` (local MQTT broker)
3. Regenerate screenshots and look at them (readability of medallions, clipping, outlines, HUD overflow at 1280px and 390px widths).
